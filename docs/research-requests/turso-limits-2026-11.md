# 調査依頼: Turso Cloud の制限（2026年11月時点）

技術記事で「D1・Turso・Cloudflare Durable Objects のそれぞれで、アカウント（ユーザー）ごとに SQLite の DB を1つ持たせる設計」を比べます。その比較表のうち Turso の欄を、公式の一次情報で埋めたいです。

## 調べてほしいこと

一次情報（docs.turso.tech、turso.tech の料金ページ・ブログ、Turso の GitHub）を優先してください。数字ごとに出典の URL と、本文で確かめたか（本文で確認 / 検索の抜粋のみ / 見つからない）を書いてください。見つからないものは「見つからない」と書き、推測で埋めないでください。

1. **DB 1つの大きさの上限**
   - プラットフォームが決める、1つの DB の最大サイズはあるか（有料プランの Developer・Scaler で）
   - プランの保存量（Developer 9GB など）は、全 DB の合計か。1つの DB がプランの保存量を超えられるか（超過料金を有効にした場合を含む）
   - `--size-limit`（作成時に自分で決める上限）の仕様
   - libSQL と Turso Database（Rust 版）で上限が違うか
2. **DB の数と作成**
   - 有料プランで DB の数は本当に無制限か。「アクティブな DB」の数や、月に使った DB の数に上限や課金はあるか
   - Platform API で DB を作る・消すときのレート制限、作成にかかる時間
   - グループ（場所）あたりの DB の数に上限はあるか
3. **1つの DB への負荷の制限**
   - 1つの DB への同時接続数、毎秒の要求数、1回の問い合わせの時間や結果の大きさ、行や BLOB の最大サイズ
   - 書き込みのコミットに足される待ち（Developer で最大 50 ミリ秒、という記述が今もあるか）
4. **スキーマの変更を全 DB に配る方法**
   - Multi-DB Schemas は新規ユーザーに使えないままか。代わりの公式の手順や道具はあるか
5. **DB をまたぐ処理**
   - ATTACH（複数の DB を1つの接続で読む）は新規ユーザーに使えないままか
6. **削除と保持**
   - 消した DB が復元できる期間（有料プランで5日、という記述が今もあるか）
   - PITR の保持期間（Developer 10日など）
7. **Supabase による買収の影響**
   - 2026年10月の買収の発表で、Turso Cloud の料金・制限・提供の継続について公式に言っていること
   - 一次情報（supabase.com のブログ、turso.tech のブログ）の URL と日付
